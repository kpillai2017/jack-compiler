🎮 Using the Compiler with JackVM

← Back to Documentation Index

This compiler turns Jack into VM code. To run that code you need a virtual machine. jackvm-py is a companion project: a Jack VM written in Python, with a game window and a live memory debugger. The two projects are in separate GitHub repositories. You clone and install them separately, and neither one needs the other. When both are installed, each adds a shortcut to the other.

In one sentence: press Ctrl+J in the compiler's window to play your program in JackVM, or point JackVM straight at a folder of .jack files and it compiles them for you.

1. Set it up

The easy way: one Python environment

Clone both repositories side by side and install both into the same virtual environment. They then find each other automatically, with no configuration:

git clone https://github.com/kpillai2017/jack-compiler.git
git clone https://github.com/kpillai2017/jackvm-py.git
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -e "./jack-compiler[gui]" -e ./jackvm-py

Check it worked:

jackc --version      # jackc 1.x
jackvm --version     # jackvm 0.1.0

Already have them in separate environments?

That works too. The first time Ctrl+J can't find the other app, the window asks where it is: open its folder in the chooser (folders where it can run are marked [use]) and press Use this folder. The answer is saved in the shared config file, and from then on the apps find each other from any folder and any environment. You can also write the file yourself:

# ~/.config/jack-tools/config.ini
# (Windows: %APPDATA%\jack-tools\config.ini; $XDG_CONFIG_HOME is honoured,
#  and $JACK_TOOLS_CONFIG points to a different file)
[apps]
jackvm = ~/src/jackvm-py         ; searched: bin/, .venv, venv, env, .direnv/*
jackc = ~/src/jack-compiler      ; jackc-gui is found there too
# jackc-gui = /full/path/to/jackc-gui   ; a command works as well
# jackvm = off                          ; hide the shortcut

Both repositories include a commented template with every setting, config.example.ini. Copy it into place and uncomment the lines you need:

mkdir -p ~/.config/jack-tools
cp config.example.ini ~/.config/jack-tools/config.ini

Each app also looks for the other on your PATH, or you can point to it with an environment variable, which beats the config file:

# tell the compiler where JackVM is
export JACKVM="$HOME/src/jackvm-py/.venv/bin/jackvm"

# tell JackVM where the compiler is
export JACKC="$HOME/src/jack-compiler/.venv/bin/jackc"
export JACKC_GUI="$HOME/src/jack-compiler/.venv/bin/jackc-gui"

2. From the compiler to JackVM

Open your program in the compiler's window and press Ctrl+J:

jackc-gui projects/09/Square/
  • What runs: every .jack file in the same folder as the selected tab. In nand2tetris one folder is one program. If you compiled a whole tree with -r, you run the program you're looking at.
  • Only working code runs. If any file in that folder has an error, Ctrl+J says Fix the errors in Main.jack first. Press Ctrl+E to jump to it.
  • Nothing is written next to your sources. The VM code goes to a fresh temporary folder, so it works with --no-write too. JackVM brings its own Jack OS (Math, Screen, Output, ...), so only your classes are needed.
  • Edit, then run again. Change your code in any editor, press Ctrl+R to recompile and Ctrl+J to run. The old JackVM window closes and a new one opens.
  • Crashes are reported. If JackVM stops with an error, its last message appears at the bottom of the compiler's window.

3. From JackVM to the compiler

Run Jack source directly

jackvm projects/09/Square/            # compiles the .jack files, then runs them
jackvm projects/09/Square/Main.jack   # one file means its whole folder

Without a path, jackvm opens its file picker. When the compiler is installed, the picker also lists .jack files and offers [compile+play N .jack] next to folders of Jack source. If a folder has both .jack and .vm files, the .jack files win, because they're the ones you've been editing.

When the code has a mistake

The compiler's message is shown, and you can jump straight into the compiler's window:

Can't compile Square/: Main.jack:3:7: error: 'x' is not declared - Ctrl+J: open in compiler

Pressing Ctrl+J opens jackc-gui on that folder, with every mistake marked under the faulty line. Fix it there and press Ctrl+J again to run it back in JackVM.

While a program is running, Ctrl+J in JackVM also opens its sources in the compiler.

4. How each app finds the other

Both apps use the same small module, integrations.py. An identical copy lives in each repository, and a test checks that the copies match. It tries four things in order and uses the first that works:

#Where it looksExample
1An environment variable: JACKVM, JACKC, JACKC_GUI. Set it to off to hide the shortcut.JACKVM="python3 -m jackvm"
2The config file ~/.config/jack-tools/config.ini, section [apps], keys jackvm, jackc, jackc-gui. A value is the project's folder (its bin/, .venv, venv, env and .direnv/* are searched; a checkout with only its requirements installed is run from source with that environment's Python) or a command; off hides the shortcut. Ctrl+J's folder chooser writes it for you.jackvm = ~/src/jackvm-py
3The same Python environment: both packages register in the jack_tools entry-point group in their pyproject.toml.pip install -e ./jackvm-py
4The PATH: a jackvm / jackc / jackc-gui command installed anywhere.pipx install ./jackvm-py

If nothing is found, the shortcut is still listed, as Ctrl+J find JackVM...: pressing it opens the folder chooser. If the folder you put in the config file has no jackvm in it, the terminal says where it looked.

Why not just import each other?

  • Independent repositories. The apps only call each other's command line (jackvm <folder>, jackc <folder> -o <folder>, jackc-gui <folder>). Either one can change its internals, or be an older or newer version, and they still work together.
  • One window per program. Both are pygame apps, and pygame supports a single window per process. Running JackVM as its own process gives it its own window, and a crash there can't take the compiler down.
  • No hard dependency. Neither pyproject.toml lists the other, so each repository installs, tests and runs on its own.
  jackc-gui ──Ctrl+J──▶  jackvm <temp folder of .vm files>
     ▲                                │
     │                        (Jack source given?)
     │                                ▼
     └──Ctrl+J── jackc-gui <folder>   jackc <folder> -o <temp>  ──▶ play

5. Troubleshooting

You seeTry
Ctrl+J find JackVM...Press it and choose your jackvm-py folder. If no folder is marked [use], JackVM isn't installed in it yet: run python3 -m venv .venv && .venv/bin/pip install -e . there (pip install -r requirements.txt is enough too).
Ctrl+J JackVM (not installed)The lookup is switched off: JACKVM=off, or jackvm = off in the config file. After changing an environment variable, restart jackc-gui: that lookup happens when the window opens.
It worked, then stopped after you moved a folderEditable installs remember the old location. Run pip install -e again from the new place. Stale installs are skipped, and the lookup falls back to the PATH.
Fix the errors in X.jack firstAnother file in the same folder doesn't compile. Its tab is red, and Ctrl+E jumps to the problem.
JackVM stopped (exit 1): ...The program loaded but crashed, or JackVM couldn't load it. Run it from a terminal with jackvm <folder> to see the full message.
JackVM plays old codePress Ctrl+R in the compiler first. Ctrl+J runs the last compile, not unsaved edits.
Windows: a path in JACKVM with spacesPut it in double quotes: set JACKVM="C:\Program Files\jackvm\jackvm.exe"
