The Big Picture: What is a Compiler?

A compiler is a program that translates source code from one language into another. Think of it like a translator that converts English into another language.

Simple Example: You write code in Jack (which is easy to read), but computers understand VM code better. The compiler translates Jack → VM code.

The Jack Compiler specifically translates Jack source code (.jack files) into Hack Virtual Machine code (.vm files).

The Compilation Pipeline

Our compiler processes your code through four main stages:

Source Code
→
Lexer
→
Parser
→
Code Gen
→
VM Code

Stage 1: Lexer (Tokenization)

The lexer reads your Jack source code character by character and breaks it into meaningful pieces called tokens.

Example:

Input: let x = 5;

Output tokens:

[LET] [IDENTIFIER: x] [ASSIGN] [NUMBER: 5] [SEMICOLON]

This step removes unnecessary whitespace and comments, leaving only the meaningful symbols.

Stage 2: Parser (Syntax Analysis)

The parser takes the tokens and checks if they follow the grammar rules of Jack. This is where ANTLR4 comes in!

What is ANTLR4?

ANTLR4 is a parser generator - a tool that automatically creates a parser from a grammar. The grammar is a formal description of valid Jack syntax.

The parser builds a parse tree showing the structure:

Program └── ClassDeclaration └── Subroutine ├── Name: "main" └── Statements └── LetStatement ├── Variable: "x" └── Expression: 5

Stage 3: Visitor Pattern (Semantic Analysis)

We use the Visitor Pattern to traverse the parse tree and build a symbol table.

What's a Symbol Table?

A symbol table is like a dictionary that keeps track of all variables in your program:

Variable x: - Type: int - Kind: local - Index: 0 Variable sum: - Type: int - Kind: static - Index: 0

During this stage, we also check for errors like using undefined variables or type mismatches.

Stage 4: Code Generator (Translation to VM)

Finally, we generate Hack VM code. For each construct in the Jack program, we emit the equivalent VM instructions.

Example:

Jack: let x = 5;

VM Code:

push constant 5
pop local 0

Understanding ANTLR4

What Problem Does ANTLR4 Solve?

Writing a parser from scratch is very complex. You need to handle:

  • Operator precedence (multiplication before addition)
  • Nested structures (expressions within expressions)
  • Different statement types
  • Error recovery

ANTLR4 automates all of this! You write a grammar (a formal description of the language), and ANTLR4 generates the parser.

The Grammar: Teaching ANTLR4 About Jack

Our grammar file (grammar/Jack.g4) is like a recipe that says:

Example Grammar Rules:

// A class is: class NAME { members }
classDeclaration
    : CLASS className LBRACE 
      classVarDeclaration* 
      subroutineDeclaration* 
      RBRACE
    ;

// A statement can be: let, if, while, do, or return
statement
    : letStatement
    | ifStatement
    | whileStatement
    | doStatement
    | returnStatement
    ;

This grammar tells ANTLR4 how Jack programs should be structured. ANTLR4 then generates a parser that validates any Jack code against these rules.

The Visitor Pattern

Once ANTLR4 has created a parse tree, we need to process it. We use the Visitor Pattern, which is like a tour guide visiting each node of the tree.

How the Visitor Works:

  1. Start at the root of the parse tree
  2. Visit each node (class, method, statement, etc.)
  3. For each node, perform appropriate actions (build symbol table, generate code)
  4. Recursively visit child nodes
Visitor travels: Program ↓ visit_program() ClassDeclaration ↓ visit_class_declaration() Subroutines (visit each) ↓ visit_subroutine_declaration() Statements (visit each) ↓ visit_statement()

Key Design Patterns Used

1. Visitor Pattern

Purpose: Separate the structure (parse tree) from the operations (code generation).

How it works: Instead of adding code generation logic to the parse tree nodes, we have a separate Visitor class that walks through the tree and performs operations. 

def visit_let_statement(self, ctx):
    # Handle let statement
    var_name = ctx.varName().getText()
    # Evaluate expression
    # Generate code to assign value to variable

2. Symbol Table Pattern

Purpose: Keep track of all variables and their properties.

How it works: Maintain a dictionary of all variables with their type, kind (local/field/static), and index. 

# When we see "var int x;"
symbol_table.define("x", "int", VarKind.LOCAL)

# Later, when we use x:
symbol = symbol_table.get_symbol("x")
# Returns: {name: "x", type: "int", kind: LOCAL, index: 0}

3. Code Generation Pattern

Purpose: Generate VM code incrementally as we traverse the parse tree.

How it works: Maintain a list of VM instructions and emit new instructions for each construct encountered. 

# For: let x = 5;
codegen.push_constant(5)      # push constant 5
codegen.pop_variable("x")      # pop local 0

Example: Compiling a Simple Statement

Let's trace through the compilation of: let x = 5;

Step 1: Lexer (Tokenization)

Input: let x = 5;
Output: [LET] [IDENTIFIER:x] [EQUAL] [NUMBER:5] [SEMICOLON]

Step 2: Parser (Build Parse Tree)

LetStatement
  └── varName: "x"
  └── expression
      └── term
          └── integerConstant: 5

Step 3: Visitor (Generate Code)

visit_let_statement():
  - var_name = "x"
  - expression = 5
  - visit_expression() → generates: push constant 5
  - pop_variable("x") → generates: pop local 0

Step 4: Code Generator (Output)

push constant 5
pop local 0

Handling Complex Constructs

Expressions with Operators

Jack expressions follow operator precedence (multiplication before addition).

Jack: 1 + 2 * 3

Parse tree (respecting precedence):

Expression
      ├── term: 1
      ├── op: +
      └── term
          ├── 2
          ├── *
          └── 3

VM Code (multiplication done first):

push constant 1
push constant 2
push constant 3
call Math.multiply 2
add

Control Flow (if/while)

For control flow, we generate labels and conditional jumps.

Jack: while (i < 10) { i = i + 1; }

VM Code:

label WHILE$0
push local 0          // push i
push constant 10
lt
not
if-goto ENDWHILE$1
push local 0          // i
push constant 1
add
pop local 0           // i = i + 1
goto WHILE$0
label ENDWHILE$1

Method Calls

When calling a method on an object, we need to push the object as the first argument.

Jack: i.push(5) where i is of type Image

VM Code:

push local 0          // push object i
push constant 5        // push argument
call Image.push 2      // call with 2 args (this + value)

Memory Management in the Hack VM

The Hack VM uses different memory segments for different variable types:

Jack Variable Kind VM Segment Example
local local var int x; → local 0
argument argument function parameter → argument 0
field this field int x; → this 0
static static static int count; → static 0

Our compiler automatically assigns indices to variables and generates the correct push/pop instructions with the appropriate memory segment.

Two-Pass vs Single-Pass Compilation

Our compiler uses single-pass compilation, meaning it processes the code once from beginning to end.

Efficiency: Single-pass compilation is faster than two-pass, which is important for large projects.

As we traverse the parse tree with the Visitor, we simultaneously:

  1. Build the symbol table
  2. Generate VM code
  3. Check for errors

Error Handling

The compiler detects and reports three categories of errors:

1. Lexical Errors

Invalid characters or malformed tokens

2. Syntax Errors

Grammar violations (detected by ANTLR4 parser)

Example: Missing semicolon

Error: Expected ';' but found 'let'

3. Semantic Errors

Logical issues (detected during code generation)

Example: Using undefined variable

Error: Undefined variable: unknownVar
